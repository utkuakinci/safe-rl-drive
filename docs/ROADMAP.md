## Week 1 — environment, PPO & RecurrentPPO baselines, W&B

- [code] Shared observation/action contract for all scenarios (`envs/spec.py`, `envs/scenarios.py`):
  Kinematics 8×7, fixed normalisation ranges, unified 5 meta-actions, 2 Hz decisions.
- [code] Scenarios: highway lane change, merge, intersection (+ roundabout / dense highway held out).
- [code] PPO (SB3) and RecurrentPPO (sb3-contrib) configs with `extends:` inheritance; partially
  observable variant (`mask_features: [vx, vy]`) — the setting where recurrence should pay off.
- [code] W&B tracking (TensorBoard sync, `eval/*` driving KPIs, best-model checkpointing) and Bayesian
  sweeps (`configs/sweeps/`).
- [run] `make train` (3 scenarios × 2 algos × 5 seeds, ~300k steps each) and `make train-pomdp`.
- [run] One sweep per algorithm on highway (~30 runs × 150k steps).

## Week 2 — evaluation, robustness, safety shield

- [code] Driving KPIs per episode: success, collision, off-road, mean speed, RMS / max jerk, lane changes.
- [code] Two-level aggregation (episodes → per-seed → mean ± 95 % Student-t CI across training seeds).
- [code] Robustness suite: Gaussian sensor noise (σ = 0.02/0.05/0.10), 20 % missed detections, 1-step
  actuation delay, 1.5× / 2× traffic density, unseen scenarios.
- [code] Rule-based safety shield (TTC, dynamic gap, lane-change gap/TTC, crossing-traffic CPA, AEB) on a
  separate safety channel, with per-rule intervention logging; probability-aware fallback.
- [code] Explainability: integrated gradients (completeness-tested) + gradient×input, per-vehicle
  importance, one-line natural-language rationale, annotated episode videos.
- [run] `make eval` → `results/<scenario>/summary.md`; `make explain` → videos for the README.

## Week 3 — ONNX / TensorRT, C++ ROS2 node, benchmark

- [code] ONNX export of the actor (feed-forward and LSTM with explicit state I/O), interface contract in
  ONNX metadata, automatic parity check vs PyTorch.
- [code] TensorRT FP32 / FP16 / INT8 (entropy calibration on recorded on-policy observations).
- [code] Benchmark: PyTorch vs ONNX Runtime vs TensorRT — p50/p99 latency, throughput, host/GPU memory,
  artefact size, logit error, action agreement, closed-loop success/collision per backend.
- [code] C++ ROS2 node (component + executable): ONNX Runtime and TensorRT backends, recurrent state on
  device, C++ port of the shield verified against 2400 Python reference vectors (gtest), latency stats.
- [code] highway-env ↔ ROS2 lock-step bridge, launch file, Docker image, CI closed-loop run.
- [run] `make deploy` on a CUDA machine → `results/benchmark_*/benchmark.md` (the README's headline table).

## Week 4 — CARLA demo, README, Active Inference

- [code] CARLA 0.9.15 demo: same ONNX artefact + shield, observation contract rebuilt from CARLA ground
  truth, meta-action → pure-pursuit/PI controller, annotated video.
- [code] Active inference (pymdp) vs PPO vs RecurrentPPO on a lane-choice POMDP with a distance-dependent
  noisy detector: sample efficiency, robustness to a worse sensor, decision latency.
- [code] MetaDrive sim-to-sim transfer (`make metadrive`, Docker): replaces CARLA on this hardware.
- [run] `make carla` (needs a CARLA server), `make aif`.
- [run] Fill README tables / GIFs from `results/`.
